## Features
- **Service Scheduling**: Requirements grouped under the "Service Scheduling" capability
- **Work Orders**: Requirements grouped under the "Work Orders" capability
- **Telematics Odometer Ingestion**: Requirements grouped under the "Telematics Odometer Ingestion" capability

### User roles
- **Administrator**: Privileged user who configures the platform and manages users, roles, content, and settings.
- **Manager**: Oversees a functional area and approves or supervises the work within it.
- **Technician**: Carries out assigned maintenance or service work and records its completion.

            router.py - GET /vehicles, POST /vehicles, GET /vehicles/{vehicle_id}, PUT /vehicles/{vehicle_id}

            service.py - Vehicle register CRUD; joins to depot, vehicle_type, schedule; reads vehicle_service_due_mv

            router.py - POST /vehicles/{vehicle_id}/odometer-readings (manual); POST /telematics/ingest (telematics feed...

            schemas.py - WorkOrderIn, WorkOrderClose, WorkOrderOut Pydantic schemas
            service.py - Work order lifecycle: create (open), close with validation, reset service clock via odometer service
          dashboard/
            __init__.py - Package initialiser
            router.py - GET /depots/{depot_id}/dashboard — due and overdue vehicle lists
            schemas.py - DashboardVehicleRow, DashboardOut Pydantic schemas

        odometer_reading.py - SQLAlchemy ORM model for odometer_readings table
        work_order.py - SQLAlchemy ORM model for work_orders table
        vehicle_service_due_mv.py - SQLAlchemy mapped class for vehicle_service_due_mv materialised view (read-only)

        depot_repository.py - Data-access methods for depots
        vehicle_type_repository.py - Data-access methods for vehicle_types
        schedule_repository.py - Data-access methods for schedules

    requirements-dev.txt - Pinned development and test dependencies (pytest, httpx, pytest-asyncio)
    .env.example - Example environment variables including TELEMATICS_MODE, DATABASE_URL, JWT_SECRET

## Getting started

### Prerequisites

- Node.js 18+ and npm
- Python 3.11+
- Postgres
- Docker & Docker Compose (optional)

### Backend

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

### Frontend

```bash
npm install
npm run dev
npm run build
npm run test
```

### With Docker

```bash
docker compose up --build
```

### Environment variables

Copy `.env.example` to `.env` and set:

- `DATABASE_URL`
- `SECRET_KEY`

## API reference

| Method | Endpoint | Description |
| --- | --- | --- |
| `POST` | `/auth/login` | Obtain a JWT access token |
| `POST` | `/auth/logout` | Invalidate the current token |
| `GET` | `/auth/me` | Return the authenticated user's profile |
| `GET` | `/depots` | List all depots |
| `POST` | `/depots` | Create a depot |
| `GET` | `/depots/{depotId}` | Get a depot by ID |
| `PATCH` | `/depots/{depotId}` | Update a depot |
| `DELETE` | `/depots/{depotId}` | Delete a depot |
| `GET` | `/vehicle-types` | List all vehicle types |
| `POST` | `/vehicle-types` | Create a vehicle type |
| `GET` | `/vehicle-types/{vehicleTypeId}` | Get a vehicle type by ID |
| `PATCH` | `/vehicle-types/{vehicleTypeId}` | Update a vehicle type |
| `DELETE` | `/vehicle-types/{vehicleTypeId}` | Delete a vehicle type |
| `GET` | `/schedules` | List service schedules |
| `POST` | `/schedules` | Create a service schedule |
| `GET` | `/schedules/{scheduleId}` | Get a service schedule by ID |
| `PATCH` | `/schedules/{scheduleId}` | Update a service schedule |
| `DELETE` | `/schedules/{scheduleId}` | Delete a service schedule |
| `GET` | `/users` | List users |
| `POST` | `/users` | Create a user |
| `GET` | `/users/{userId}` | Get a user by ID |
| `PATCH` | `/users/{userId}` | Update a user |
| `DELETE` | `/users/{userId}` | Deactivate or delete a user |
| `GET` | `/vehicles` | List fleet vehicles |
| `POST` | `/vehicles` | Add a vehicle to the register |
| `GET` | `/vehicles/{vehicleId}` | Get a vehicle by ID |
| `PATCH` | `/vehicles/{vehicleId}` | Update a vehicle record |
| `DELETE` | `/vehicles/{vehicleId}` | Remove a vehicle from the register |
| `GET` | `/vehicles/{vehicleId}/odometer-readings` | List odometer readings for a vehicle |
| `POST` | `/vehicles/{vehicleId}/odometer-readings` | Record a manual odometer reading |
| `GET` | `/vehicles/{vehicleId}/odometer-readings/{readingId}` | Get a single odometer reading |
| `POST` | `/telematics/ingest` | Ingest an odometer reading from a telematics feed |
| `POST` | `/telematics/ingest-mock` | Ingest a simulated telematics reading (test mode) |
| `GET` | `/work-orders` | List work orders |
| `POST` | `/work-orders` | Raise a new work order |
| `GET` | `/work-orders/{workOrderId}` | Get a work order by ID |
| `PATCH` | `/work-orders/{workOrderId}` | Update a work order |
| `DELETE` | `/work-orders/{workOrderId}` | Cancel or delete a work order |
| `POST` | `/work-orders/{workOrderId}/close` | Close a work order with completion notes and post-service odometer |
| `GET` | `/work-orders/mine` | List work orders assigned to the authenticated technician |
| `GET` | `/service-due` | List vehicles with service due status |
| `GET` | `/service-due/{vehicleId}` | Get service due status for a specific vehicle |
